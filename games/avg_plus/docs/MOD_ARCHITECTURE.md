# avg_plus：微内核与全 Mod 架构

## 目录与分工

- `assets/foundation`：不依赖 Cocos、AVG 或卡牌的接口、事务执行器、快照与异步任务生命周期。负责人维护公共协议。
- `assets/mods/base-shell`：Cocos 入口、目录与页面路由；启动菜单本身也经过普通 Mod 的动作/渲染流程。
- `assets/mods/base-card`：完整高低接龙模块，规则、结算、页面适配与默认表现同属一个模块。
- `assets/mods/base-avg`：完整 AVG 模块，剧情推进、内容读取、页面表现同属一个模块。
- `assets/mods/packages`：奖励变体、剧情分支、表现风格示例；以完整能力为单位，禁止把按钮或单条动画都做成独立 Mod。
- `assets/mods/shared`：Cocos 表现适配工具，不属于规则内核。
- `assets/art`：图片、字体、场景素材、prefab、内容与运行配置。原 resources、剧情 Bundle 的逻辑加载名保持不变。

基础框架维护者负责协议和故障机制；模块负责人可以同时编写逻辑与表现；内容负责人维护资产、布局、关卡和效果配置。表现脚本也可以由美术借助 Codex 编写，但修改公共接口或规则需相关负责人审核。禁止多人同时改同一个 prefab；资产与对应 `.meta` 一起提交。

## 执行协议

`setup → load → [beforeAction → execute → beforeCommit → 校验 → 提交 → afterCommit → render 任务 → afterRender] → dispose`

仅 load、beforeAction、表现任务及 dispose 可以异步。setup/execute/beforeCommit/afterCommit/render/afterRender/validate 返回 Promise 会报错。render 同步返回顺序任务列表，每项可声明 parallel 子任务。load 在第一版按确定顺序串行进行；模块内部可并行加载独立资源。

依赖先于被依赖方执行，再按 order、ID 稳定排序。每个动作只允许一个 execute 处理器，其他模块通过钩子参与。每个玩法会话仅装配该作用域的模块。运行中不切换规则组合。

beforeAction 用于异步准备与预检，动作输入为冻结副本；可在候选 draft 中准备数据或设置 result，execute 再计算结果。没有合法 execute 的动作被拒绝。ctx.reject(reason) 拒绝动作，不提交任何状态。异常与非法候选结果也不提交。

## 状态、事务、回撤

每个模块以自己的 ID 注册纯 JSON 状态；不可存 Node、Promise、类实例、undefined、NaN 或循环引用。所有模块共享一次候选事务，所有 validate 同步通过后发布深拷贝且冻结的状态。不要在钩子中写全局变量、引擎节点或外部服务来表达尚未提交的玩法结果。

ctx.recordUndo() 记录整个组合的前后状态。默认回撤每个模块的状态；特殊模块可实现 restoreUndo(previous,current,after)。卡牌模块保留消费次数，以实际金币净变化计算回撤；奖励倍率 Mod 同样参与回撤。异常回滚与玩家回撤语义不同。

快照接口 exportSnapshot/restoreSnapshot 仅在会话空闲时使用，记录模块清单、版本、配置指纹和历史。不兼容快照直接拒绝，不静默恢复。不含云存档或玩家存档界面；如需持久化，可由新的存档 Mod 使用这个协议。卡牌随机数状态属于模块状态，参与快照与回撤。

## 异步与故障

TaskScope 管理取消、截止时间和清理。资源接口不支持真实取消时，仍须忽略过期结果，并用 discard 回收迟到的资源。子任务结束会执行所登记的清理；跨任务资源应由会话/模块持有并在 dispose 释放。

页面离开：先取消会话，再反向卸载模块。准备阶段失败不提交；表现失败保留提交状态并调用 afterRender 恢复画面。默认每个 load/beforeAction 限时 8 秒、整次表现 20 秒、单任务默认 5 秒（上限 15 秒）、单模块卸载 1 秒。截止时间可通过 RuntimeOptions 设置。

相同会话的外部重复输入返回 busy，不积压点击。afterCommit/afterRender 可 enqueue 后续动作，不返回可等待的下一动作 Promise；自动动作链最多 16 个。未登记的 fire-and-forget 工作不受保护，禁止用于关键流程。

脚本是可信代码，不是安全沙箱。同步死循环、直接越权改全局状态无法靠 Promise 超时解决，需代码审核和自动测试。模块失败不会被静默替换成另一套规则。

## 边界

新增 TS 脚本、注册新工厂后需要重新构建。配置与资源修改通过 Cocos 重新导入并在重新进入会话时读取；不承诺远程原生脚本热更新。暂不做在线 Mod 商店、浏览器编辑器或可视化流程图系统。


## 执行顺序与接入选择

order 是同一依赖条件下的优先级，不允许通过较小数字绕开 requires。基础 AVG/卡牌 order=100，玩法变体 order=200，表现风格 order=300。优先把真实前后关系写进 requires；同级 order 相同再按 ID 排序，避免依赖文件扫描顺序。

规则扩展读取或修改 ctx.draft['base-card'] / ctx.draft['base-avg']，同时维护自己的命名空间，并声明依赖。未能通过基础模块 validate 的变更会使整个动作失败。替换整套基础玩法时，由新包实现动作合约并在装配点选用它，不能同时启用两个相同动作处理器。

本次没有引入每个节点都可重写的虚函数系统。扩展入口以加载、动作准备、规则提交前后、整段表现和卸载为单位；复杂新能力优先在包内分文件和类，不继续细拆内核钩子。

## 对需求的评价

这套结构能让基础玩法持续验证公共串联能力，也让后续 Mod 有完整示例。美术效果可带自己的行为与数值：已有能力通过配置接入，新的行为通过脚本包接入。三层目录、配置组合、明确动作归属能减少两人修改同一文件的机会。

代价是脚本 Mod 仍需要编译、接口理解和测试；Git 目录本身不能阻止别人越界修改；任意脚本的安全隔离也不是本框架提供的能力。并行仅用于显式独立的表现任务，结算保持单次同步事务，以降低顺序与回撤复杂度。这个粒度适合当前 AVG + 卡牌规模。

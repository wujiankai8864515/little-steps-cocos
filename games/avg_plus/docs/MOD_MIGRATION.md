## 已实现的关键保证

- 基础卡牌与 AVG 都使用 Mod 合约。基础层不导入 cc、mods 或 art，检查脚本验证这个边界。
- 依赖先行，然后 order 和 ID 决定顺序。一个动作只有一个 execute，扩展在提交前后和表现阶段参与。
- 结算在同步事务内完成，异步加载或动画不参与半次结算。提交前失败丢弃候选状态，提交后动画失败保留规则状态并刷新画面。
- 退出取消等待和动画；取消后的旧资源回调不能覆盖新画面。清理可重复调用，旧任务 finally 不会再次取消新任务。
- 回撤覆盖所有 Mod 命名空间，奖励扩展和使用计数有明确语义；固定 seed 的牌局可重现。
- 原资源与 Cocos 脚本 UUID 保留，移动后的逻辑 Bundle 名保持 resources / drama_fake_fiancee。

## 运行与交接

打开 `assets/mods/base-shell/scene.scene`；默认 profile 仅启用两个基础玩法。可在 `assets/art/resources/mods/profiles/default.json` 启用示例，停止并重新预览。示例奖励规则默认关闭，避免打开工程就改变玩法数值。

先读 MOD_GUIDE.md；程序维护者同时读 MOD_ARCHITECTURE.md。根目录 AGENTS.md 为两人的 Codex 说明修改位置与验证要求。改造尚未替用户创建 Git 提交；现有未提交工作没有被 reset 或覆盖。Git 当前的删除与新增包含目录迁移，提交时应同时纳入新旧路径与 .meta。

## 尚未验证的发布边界

没有在 iOS/Android 真机编译或运行，手机尺寸的网页验证不能代替原生验收。没有建立远程协作服务器、云预览或线上发布，也没有浏览器编辑器。Mod 脚本需要可信代码审核和重新构建；当前配置按重新进入会话加载，不是远程热更新系统。

本次验证了失败与恢复的典型边界，但不承诺任意第三方脚本不会死循环或越权。新包仍需遵守同步事务、作用域清理、状态校验与回撤约定。

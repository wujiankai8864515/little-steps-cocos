# N28 衣柜正式入口候选（2026-10-07）

用户最新授权直接落地精简衣柜，取消单独样例交付/确认门槛。此提交提供生产源码候选，不能据此声称正式部署或全部链路通过。

## 实际修改与因果
- Home 的 Wardrobe 可见区域点击，先沿原触摸反馈后进入独立按需衣柜。被人物/道具遮住的柜子不抢输入；返回恢复原 Home 世界/音频端口。
- 新 wardrobe_visual 仅打开衣柜请求；outfit_visual 单独371KB衣料包在打开衣柜或恢复已穿皮肤时请求，不加入原皮 Home 首屏依赖；App 单飞加载、取消代际及迟到响应保护。保存桃花时在 Home 实例化之前 await outfit；默认原皮跳过，不能先闪原皮再变。保存皮肤的实际冷包首帧仍须整合正式包验证。
- 页面只衣柜、窗户、藤蔓、垫子和主角。2 套挂布独立顶点摆动并有同步阴影；7 串植物用受限阻尼弹簧与分段形变错相摇摆；窗玻璃反射和宽柔光束与共享昼夜一致。
- 原皮与桃花可预览。桃花衣料只通过原身体 Polygon2D 的相同 UV/骨骼/重力形变网格合成，原脸、眼、鳍、尾和动作仍为既有实现，不替换整只角色或动作图片。目录、材料及遮罩参数可配；这是一类贴身披巾材质框架，不代表任意复杂长裙/袖子无需再设计。
- 刚试穿/穿上时出现有原画材质的桃花瓣上升及四尖菱光；22 个有限粒子，关闭清理。背包保持原实现，不做背包专项。
- 原皮可直接穿上；已解锁款可保存。真实广告回调端口存在，无 provider 时明确提示暂不可用，仅预览，取消/返回不覆盖已穿衣物。不用定时器假装广告完成。当前没有真实广告供应方，这是桃花正式解锁端到端阻碍。
- 照片墙动态角色同步已穿的身体衣料；旅行背包使用用户明确暂沿用的原静态图，不重绘替换。主题旅行场景及新主题收获没有在本提交虚构实现。

## 资源
`design/wardrobe` 保留 3 张原始生成稿。`build/wardrobe/pack_assets.py` 为可复现尺寸适配/图集打包，输出2张运行PNG，不把源设计板塞入运行包。
- atlas 1974×1280；其中背景720×1280逻辑画面，6部件保1254²源图像素，非完整全页2x清晰度承诺。
- 桃花衣料1005×603，与原670×402身体坐标等比例采样；仅衣料区域参与，不替换脸。
- 2纹理RGBA8 12,530,940B；包装131,072B；运行节点/材质保守预留1,048,576B。合计13,710,588B，未测浏览器进程/GPU峰值。
- 原完整组已128条且接近256MiB，不能单凭本候选判资源准入通过。总集成在核实际启动→游戏阶段释放证据并重新审计，不能抬硬顶。

## 已做的有限验证
- 官方Godot4.5.2（固定引擎）加载7ba核心/house/exterior PCK，再挂本次源候选模块和运行PNG，7个模块编译并真实实例化页面。
- Mesa软件GL看实际原皮/桃花、喝水姿态、拖起网格、夜间画面，未报脚本或shader错误。字体候选用同源LXGW临时子集，正式生产需整体prepare_fonts重建，旧包字库缺字的初始失败已保留说明，不能以候选字库替代冷包验证。
- lifecycle：锁定桃花不能穿上，失败广告不解锁，模拟已验证回调可解锁，24次皮肤切换网格/rig身份不变，8次预览取消不保存，粒子/材质数量有界，关闭停止。
- bridge：真实Home实例取消迟到加载不打开、重试可开、无广告provider不解锁、关闭恢复Home、重开取消。
- 早期夹具把材质数误写19（实际20，后新增玻璃为21），仅修夹具断言并复跑；没有把失败当产品已通过。

# 旅行木鱼工程执行与发布约束

这些约束适用于 framework、games、build 及全部交付物。修改产品前先读本文件、build/PRODUCTION.md、本轮唯一验收清单。旧编号清单仅作历史，不能替代最新用户要求。

## 源码先于打包部署

1. 每个修复独立原子提交：完成一个并取得该项验证后立即提交，不攒多项 squash。中文说明必须含事项ID、实际修复内容，以及代码/资源/运行验证结果；未验证只能写候选或待验，禁止写“已修好”。修复映射到用户最新消息，过时要求标 superseded，不恢复已取消玩法。当前追踪见 build/followup_20261006/requirements.json 与历史32账；两者必须区分代码、资源、冷包与可观察结果。
2. 每个修复提交后立即交根线程同步 GitHub，逐项保留提交对应关系；正式部署批次再冻结干净源码。不得把多项工作在远端压成一个提交丢掉对应历史。
3. 在用户已授权的私有 GitHub 仓库 little-steps 普通追加提交并 push，保留既有历史，禁止 force。恢复工程与 GitHub 历史不同，必须记录本地源码 commit → GitHub commit 的映射，不能把旧历史覆盖远端。
4. 从远端读回完整 commit/tree，核对生产源文件 blob、mode、字体许可证和新美术资源。说明仓库入口 README 的任何映射说明差异。尚未验证远端不能称已备份成功。
5. 远端核验通过后，才从同一冻结源生成正式私有部署包。准备阶段的本地专项工程、试构建必须标注为候选，不能混称最终包。不得先部署后补源码。
6. 交付清单记录本地/GitHub commit、tree、source snapshot hash、官方引擎/template hash、每个 raw 文件/PCK 的 bytes/SHA256、源码归档/bundle 与 Web/QA 对应关系。禁止以旧 Web 文件冒充新构建。
7. 官方发布前核完整 archive 展开后的容量、文件权限、路径、MIME/编码、完整性及原站旧路径回归；保持用户选择的私有权限和 origin，不擅自公开、建另一站或迁存档。
8. 源码、Git bundle、原美术、配置、构建工具和报告必须持久保存并固定版本回读；空目录独立验证恢复，不能只留临时盘。大文件可分卷，但必须检验重组 SHA 和恢复入口。

## 资源与加载硬门槛

- 唯一主线为官方 Godot 4.5.2 non-thread Web。禁止误用 PATH 中其他 Godot 版本。引擎与模板 hash 见 build/README.md。
- Home 首屏不得依赖非必需的 travel_visual 资源包。加载页只等必要登录资源；Comic 与 Home 的真实 ready、首次绘制、取消代际语义必须保留。
- Home 首屏资源下载预算 19,000,000 bytes；80 specs/batch、128 entries、256 MiB 预估准入不能为绕过失败随意调大。预估不等于浏览器内存实测。
- UI 可见代码、preload 的 _init/configure 不得提前读取未挂载图/字体。旅行资源在真正进入时按需加载，取消/失败/晚回调不得挡住或重新打开 Home。
- 每个新图必须有来源、实际查看记录、源尺寸、显示尺寸/DPR、lossless 官方导入像素核验、所属包和解码/mip 预算。不要把整母板、大原字体或源设计图塞进运行包。
- 字体须有可分发许可、固定来源/hash、离线可复现子集和完整生产文本检查；禁止口口、缺字静默 fallback、来源不清字库或原画字形伪称找回。
- 用真实动态 mount 跑冷首包、暖缓存、慢网、失败/中断、取消、重试及迟到响应。必须检查实际所请求的 PCK 和最后状态，不仅检查声明 JSON。

## 产品与视觉验收

- 当前跨历史追踪见 build/followup_20261006/history_matrix_snapshot.json 的 schema 2 current_status；其中83个去重主题是来源整理，不是验收通过数。build/visual_round6/requirements_32.json 及 baseline_status 保留当时编号和历史，不能把561的“未做”直接当作当前版本状态。每项分别记录代码、资源、实际原生包、部署、Web/用户验收，未做/部分完成/未核验分开标注。
- 分层矩阵是注明时点的冻结记录，后续正式包/部署终态用新记录追加，不能回写旧快照。合并来源存在覆盖时优先读取 active_requirement 与 scope_overrides；例如 A035 的旧半径只是比较基线，当前尺寸由 A066 覆盖，不能据旧 latest 摘要回退。当前快照已区分现网 d1 与 A035 候选，软件GL缓存诊断不能判成用户硬件/Web故障。
- 能实际渲染的必须查看画面，并覆盖常见尺寸、昼夜/灯开关和相关中断场景。CPU/单位测试数量、存在某个函数或通过几何约束，均不能冒充视觉达标。
- 原生 Mesa GL 是真实软件渲染证据，不等于用户设备 GPU、手机触感、听音、浏览器存档或 Web 内存/60fps 通过。
- 公共气泡必须共用内容区、字体测量、宽高重置、选项、尾巴、动画和安全区规则；皮肤、NPC、锚点可配置，禁止逐文案临时挪字掩盖共用缺陷。
- 保真实 alpha 输入与一击一次结算、选择暂停/取消恢复、奖励一次性收纳、存档恢复和跨页面清理。背景、遮罩或装饰不能吞无关输入。
- 认可母版与原图优先。声称“同款”“对齐”需像素/结构与实际渲染证据，不能仅抽象相似。设计图获准不等于已实现验收。
- 收藏、照片已获后续工程授权并在关联组实施；按当前源码、实际包与运行证据判断，不能继续机械沿用“仅设计”。已有实现不等于用户视觉认可；当前矩阵各层的未验边界必须保留，不得把某一阶段交付称作全部历史要求完成。

## 每次失败都要复盘与防回归

每次构建、加载、发布或产品验收失败，都须在 build/reviews/ 中写：触发条件、可复现证据、确证根因与未证假设、具体修复、对应回归、受影响提交/包、仍未验证的边界。后续发布前复核所有未关闭项。

本轮应重点复核：气泡旧 min-width/居中、主页包体与绕鳍前后遮挡、真实四尖闪光与引导动感、花盘局部/世界坐标、敲击 contact 节奏及功德一次性、字体实心/画风/缺字、Home 非必需旅行包依赖与超时计时、拖拽最高层/附属部件/投影与回位。禁止把旧一次 PASS 当成后续改动仍通过。

## 冷包实证不能由全资源工程替代

发布审查必须从空 res 根挂载精确 core/Home 包，确认未打开旅行时 Home 动效、日记翻页、文字贴图都可用；不允许测试 --path 指向全资产工程，靠物理文件或预热cache掩盖缺依赖。每个绘制分支的字体/图/材质实际所属包需核对，诊断日志出现缺资源必须失败。warm/native全资产图只能作为独立组件证据，不能等价于cold Web入口。用户否定的可见效果优先标未通过并倒查真实包，不凭旧PASS归缓存。

## 已核对的证据

- 使用最新 Godot b4f77af 的道具、背包、接收材质和地面投影源码。原 Godot 工作树未修改；原生实际 PCK 中四个 shader/include payload 与最新源码逐字节相同。
- 五层合计 120 个顶点、330 个索引，全部源 UV、拟合顶点、索引逐字节匹配原生公开检查点。绑定到已有 OriginalBody，后景四层与前景 near_band 分离，无新角色、Spine 或替代美术。
- 原 CTEX 的 11 级 WebP 缓存逐级解码并保存为无损 PNG；基础层原裁剪区域像素先验证不变，再恢复完整源尺寸。Cocos 实际纹理报告 11 级，每级 committed PNG 的解码像素都有原缓存哈希检查。图片解码和 mip 上传额外计入 4,520,328 bytes 预估准入。
- 日间 15 帧穿戴：握槌 0.5、肩骨 [113,-15.5]、尾骨 [1,1.5] 和尾部隐藏完全一致。120 个房间顶点最大差异 0.00006103515625；两引擎均显示 5 个日光投影通道，地面 951、重建 1 次。
- 夜间穿戴后脱下第 8 帧：wearAmount 和 blend 完全一致，恢复肩骨、尾骨及尾部显示；归墙代理 depth 为 180，位置最大差异约 0.0000114。两引擎均显示 10 个投影通道，地面和重建次数一致。房间顶点最大差异 0.0001220703125。
- 投影比较使用实际公开原生 world vertices 与 shader uniforms 计算预期，再对照 Cocos CPU 提交数据；最大自然光坐标差异 0.00010273、灯光差异 0.00004415。此项不是 GPU 顶点回读，也不是微信实机证明。
- 87 项原/穿戴检查后新增原 mip 像素与预算检查，最终 88 项通过。生产类型和实际 Creator 导入后的候选类型通过。最终夜间浮点透明度材质实际构建、首次绘制、当前 URL 错误为零；构建 exit 36 与 Finished 日志及可见画面一起核验。
- 源冻结核对通过；用户 15 项初始文件、Boot/场景 UUID 未改变；框架软链接目标仍 0444、目录 0555，框架发行哈希不变。通用框架无游戏背包依赖。生产 59 项既有 metadata 已对 HEAD 核查，仅 Creator ver/files 自动更新和声明的 mipfilter 改动，全部 UUID 不变；新目录 metadata 来自实际导入。

## 保留的失败与修复

1. Godot noon-v1 在 prepared Home 阶段设置穿戴，之后原 pause_page/reset_motion 恢复到墙上。公开日志曾为 worn，实际最终截图为 hanging，不能验收。候选、截图和 HTTP 日志保留。noon-v2 改为原 HomePage input_enabled 后一次 call_deferred，调用真实穿戴 API，然后核对最终图和同状态日志。
2. 首次候选类型检查在 Creator 生成 temp/tsconfig.cocos.json 前执行，失败日志 M04-worn-candidate-types-v1.log 保留。实际导入后 v2/v3 与最终夜间候选通过；不修改引擎类型规避错误。
3. 第一版仅基础纹理层，缺少原 mipmap；noon-v1 对照图保留。导入全部原缓存级别后 noon-v2 实测 11 级，并记录剩余差异。
4. 归墙 v1 使用 Sprite Color 的 8 位 alpha。最终版改为 home-part 浮点材质参数，保留 v1 与 v2 对照、源码和构建日志；其余材质默认 alpha 为 1。
5. 官方 raw 源文件请求受到沙箱/证书校验失败；未放宽 TLS。改用正常 TLS 的 GitHub 官方 API，验证 Git blob 后保存过滤实现证据。
6. Python py_compile 默认缓存试图写入工作区外，失败；改用任务专用 /private/tmp/little-steps-cocos-python-cache，验证通过，无用户全局缓存配置修改。
7. Creator 的恢复 JSON、压缩 fallback、启动计时与退出诊断保留在完整 build 日志；只有 Finished、实际非空首次绘制、类型和冻结核对一起支持本项局部构建结论。
